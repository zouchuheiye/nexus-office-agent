### 关键依赖与并行规则

- M21→M22→M23→M24 是不可并行跨越的执行关键路径；没有真实独立 Runner 不得接微 VM，没有微 VM 不得开放 Shell/Git 写能力。
- M25 的 Registry 数据模型可在 M24 后半段设计，但 ResourceLoader 切换必须在 G-028 后；M26 必须消费 M25 的不可变能力摘要。
- M27 的审批领域可提前复用现有 R3/R4 内核，但 Pi Tool 暂停/恢复与 `submit-change` 只能在 G-030 后启用。
- M28 的 Session Tree 可与 M27 后半段并行开发；E-056 已形成本地 Tree/Profile/Delegation 控制面，但受限 Sub-Agent 的真实执行必须等 G-031 的策略/审批能力通过。
- M29 只对已经冻结的 API 版本做前端；未通过 Gate 的动作显示“不可用/待配置”，不得用 Fixture 冒充。E-057 的员工工作台只调用实际本地 API/SSE，未生成模型回复或虚构执行结果；审批、submit-change、PR/合并/发布和治理写操作保持禁用。
- M30 的基础遥测从 M21 即开始埋点，但成本 Gate、评测基线和配额执行在端到端链路稳定后统一验收。
- M31 必须针对最终候选镜像、策略、Registry 摘要和网络拓扑执行；早期安全单测不能替代该阶段。
