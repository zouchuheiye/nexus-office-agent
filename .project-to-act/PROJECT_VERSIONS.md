### 版本与迁移纪律

- 版本号只在相应 Gate 通过并形成新鲜 E 证据后创建；规划行不是已发布版本。
- 数据库使用 expand/contract：先新增 nullable/默认兼容结构，再双读写和回填，至少跨一个稳定版本后才允许删除旧结构。
- 公共 API 只在 `/api/v1` 内做向后兼容追加；字段删除、语义改变或错误码收窄必须进入新 API 版本和 D 记录。
- Runner 协议、RunManifest、事件、Tool Schema、Skill/MCP/Policy/Profile 都携带独立 `schema_version`/`digest`，控制面至少兼容当前和上一 Runner 版本。
- OCI 镜像、Skill/Package/Extension、策略包和前端静态制品必须签名并可定位上一已批准摘要；`latest` 不得用于生产解析。
- 回退不能删除 Session/Event/Audit/Git/Artifact 事实；只能停止新写、恢复兼容代码或撤销能力。出现跨租户、逃逸、签名绕过或未知高风险副作用时，不允许带风险继续灰度。
